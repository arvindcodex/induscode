IndusCode configuration lives in two scopes:

- **Global configuration** in `~/.induscode/` (applies globally across all IndusCode applications, including IDE, CLI, and SDK)
- **Project configuration** in `.induscode/` (applies only to the current workspace)

## Configuration Directory Layout

IndusCode stores shared configuration across a few well-known locations. The primary root is `~/.induscode/`, with structured app state under `~/.induscode/data/`:

```text
~/.induscode/
  data/
    settings/
      providers.json           # API keys and provider configuration
      global-settings.json     # Global settings
      induscode_mcp_settings.json  # MCP settings
    teams/                     # Team state
    sessions/                  # One folder of messages per session
    db/                        # SQLite databases (sessions.db, cron.db, ...)
    logs/                      # CLI and hub logs
  rules/                       # Global rules
  workflows/                   # Global workflows
  hooks/                       # Global hooks
  skills/                      # Global skills
  agents/                      # Global agent definitions
  plugins/                     # Global plugins (.js, .ts)
  cron/                        # Global cron specs
```

Additional global search paths supported by the code:

```text
~/Documents/IndusCode/
  Rules/                       # Additional global rules
  Hooks/                       # Additional global hooks
  Plugins/                     # Additional global plugins
  Workflows/                   # Additional global workflows
```

Project-level configuration lives in `.induscode/` at your repository root:

```text
.induscode/
  rules/                       # Project rules
  workflows/                   # Project workflows
  skills/                      # Project skills
  hooks/                       # Lifecycle hooks
  agents/                      # Project agent definitions
  plugins/                     # Project plugins
```

Notes:

- Global provider settings, global settings, and MCP settings are stored under `~/.induscode/data/settings/`.
- Global rules, workflows, hooks, skills, agents, plugins, and cron specs resolve directly under `~/.induscode/`.
- Rules, hooks, plugins, and workflows may also be discovered from `~/Documents/IndusCode/` for compatibility.
- In a project, IndusCode also reads the older `.induscoderules/` layout (rules, plus its `workflows/`, `skills/` and `hooks/` folders), `AGENTS.md` at the project root, and skills in `.agents/skills/`. Globally, it also reads `~/.agents/AGENTS.md` and skills in `~/.agents/skills/`.

## What Goes Where?

- Use **global (`~/.induscode/`)** for defaults shared across all IndusCode applications (IDE, CLI, SDK) on your machine.
- Use **project (`.induscode/`)** for team-shared behavior that should travel with the repo.

Commit `.induscode/` files you want to share with your team. Keep secrets out of the repo.

## Configure Through the CLI

Use the interactive config UI:

```bash
induscode config
```

From there, you can view/edit:

- Settings (global + workspace)
- Rules
- Skills
- Hooks

## Useful Configuration Commands

Use a custom configuration directory:

```bash
induscode --config /path/to/custom/config "your task"
```

Or via environment variable:

```bash
export INDUSCODE_DIR=/path/to/custom/config
induscode "your task"
```

Open the CLI log file (`~/.induscode/data/logs/induscode.log`, or the file `INDUSCODE_LOG_PATH` names) when troubleshooting:

```bash
induscode doctor log
```

## Environment Variables

| Variable | Description |
|----------|-------------|
| `INDUSCODE_DIR` | Custom configuration directory (replaces `~/.induscode/`), like `--config` |
| `INDUSCODE_DATA_DIR` | Custom data directory (replaces `~/.induscode/data/`) |
| `INDUSCODE_HUB_PORT` | Port of the local hub (default: `25463`) |
| `INDUSCODE_HUB_ADDRESS` | Hub address for `induscode schedule` commands, like their `--address` option |
| `INDUSCODE_SESSION_BACKEND_MODE` | Force backend mode (`local`, `hub`, `remote`, `auto`) |
| `INDUSCODE_SANDBOX` | Enable sandbox mode |
| `INDUSCODE_SANDBOX_DATA_DIR` | Sandbox session storage directory |
| `INDUSCODE_HOOKS_DIR` | Additional hooks directory |
| `INDUSCODE_LOG_PATH` | CLI log file (default: `~/.induscode/data/logs/induscode.log`). `induscode doctor log` opens it |

### INDUSCODE_DATA_DIR

```bash
export INDUSCODE_DATA_DIR=/custom/path/to/induscode
induscode "your task"
```

## Security Notes

<Warning>
Only use rules, hooks, skills, and plugins from sources you trust.
</Warning>

Hooks and plugins can execute code. Review them like any other executable artifact before adding them globally or to a project.
