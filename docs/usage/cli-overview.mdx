## Prerequisites

- IndusCode CLI installed (install via `npm i -g induscode`)
- Provider authenticated (`induscode auth`) — use the IndusCode Provider, IndusCodePass, or your own provider key ([Authorization Guide](/getting-started/authorizing-with-induscode#cli-setup))

## Quick Start

```bash
# Interactive session
induscode

# Run one task immediately
induscode "refactor this module to use async/await"

# Structured output for scripts
induscode --json "list TODO comments"
```

## Headless mode

Use headless mode for scripts/automation and processable output.

Headless is triggered when using flags like `--json`, when stdin is piped, or when output is redirected.

#### When headless activates

| Invocation | Reason |
|---|---|
| `induscode --json "task"` | JSON output mode |
| `cat file \| induscode "task"` | stdin is piped |
| `induscode "task" > output.txt` | stdout is redirected |

```bash
# CI/script style execution
git diff | induscode "review these changes"

# JSON for parsing: print only the final answer
induscode --json "summarize this changelog" | jq -r 'select(.type == "run_result") | .text'
```

See: [Headless Mode](#headless-mode)

### Autonomous execution

For fully unattended runs, use auto-approval:

```bash
induscode --auto-approve true "run tests and fix failures"
```

Mode selection also works in headless runs:

```bash
# plan-first
induscode -p "design migration plan"

# act immediately (default)
induscode "apply migration"
```

<Warning>
Autonomous execution can modify files and run commands without further prompts. Use a clean branch and review results.
</Warning>

## High-Value Commands

```bash
induscode --help
induscode <command> --help
```

| Command | Purpose |
|---|---|
| `induscode` | Start interactive mode or run a prompt |
| `induscode auth` | Authenticate and set provider/model |
| `induscode config` | Show the current configuration |
| `induscode mcp` | Manage MCP servers |
| `induscode doctor` | Diagnose/fix configuration issues |
| `induscode history` | Show and manage task history |
| `induscode schedule` | Manage scheduled tasks |
| `induscode hub` | Manage local hub daemon |
| `induscode kanban` | Run the Kanban app |

## Most-Used Global Flags

Source of truth: [CLI Reference](/cli/cli-reference)

| Flag | Purpose |
|---|---|
| `-p, --plan` | Start in Plan mode |
| `--auto-approve <boolean>` | Global tool auto-approval (`true`/`false`, default `true`) |
| `-m, --model <model>` | Override model for this run |
| `-P, --provider <id>` | Override provider for this run |
| `-c, --cwd <path>` | Set working directory |
| `--config <dir>` | Use config directory |
| `--data-dir <dir>` | Use isolated local state |
| `--json` | Output newline-delimited JSON messages |
| `--thinking <level>` | Set reasoning effort: `none\|low\|medium\|high\|xhigh`. Bare `--thinking` uses `medium`. Without the flag, IndusCode uses the level you last chose with `/model`, or else the provider's default |
| `-t, --timeout <seconds>` | Set task timeout |

## Automation Patterns

### Pipe context in

```bash
cat README.md | induscode "summarize key setup steps"
git diff | induscode "review for potential regressions"
```

### Chain tasks

```bash
git diff | induscode "explain these changes" | induscode "write a commit message"
```

### Restrict command execution

The CLI has no allow or deny list for shell commands. To block commands, use a `PreToolUse` hook that cancels `run_commands` calls you don't allow, like the [.induscodeignore hook](/customization/induscodeignore#enforcing-induscodeignore-with-a-hook).

### Include images in tasks

Mention an image file with `@` and the CLI attaches it to the prompt:

```bash
induscode "fix the UI shown in @./design-mockup.png"
```

### Set execution timeout

```bash
induscode --timeout 600 "run full test suite"
```

## JSON Output Schema

When you give IndusCode a task with `--json`, each line is a JSON object with a `type`. Agent events arrive as `agent_event` lines, and a `run_result` line holds the final `text` when the run finishes. The [CLI Reference](/cli/cli-reference#json-output-for-agent-runs) describes the line types.
