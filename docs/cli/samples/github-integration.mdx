## Setup

### 1. Copy the Workflow File



GitHub Actions runs workflow files in the `.github/workflows/` directory of your repository. Copy this workflow into `.github/workflows/induscode-responder.yml`:

<Accordion title="Click to view the complete induscode-responder.yml workflow">
```yaml
name: IndusCode Issue Assistant

on:
  issue_comment:
    types: [created, edited]

# No permissions by default; each job asks for what it needs.
permissions: {}

jobs:
  authorize:
    # Runs for @induscode mentions on issues, not pull requests.
    if: |
      contains(github.event.comment.body, '@induscode') &&
      !github.event.issue.pull_request
    runs-on: ubuntu-latest
    timeout-minutes: 5

    # Read-only, and uses no secrets.
    permissions:
      contents: read

    outputs:
      allowed: ${{ steps.check.outputs.allowed }}

    steps:
      # Checks the comment's author, not whoever edited it last, so that
      # editing someone else's comment doesn't start IndusCode on their text.
      - name: Check that the comment's author can write to the repository
        id: check
        env:
          GH_TOKEN: ${{ github.token }}
          AUTHOR: ${{ github.event.comment.user.login }}
        run: |
          PERMISSION=$(gh api "repos/$GITHUB_REPOSITORY/collaborators/$AUTHOR/permission" --jq .permission)
          echo "$AUTHOR has $PERMISSION permission"
          if [ "$PERMISSION" = admin ] || [ "$PERMISSION" = write ]; then
            echo "allowed=true" >> "$GITHUB_OUTPUT"
          fi

  analyze:
    needs: authorize
    if: needs.authorize.outputs.allowed == 'true'
    runs-on: ubuntu-latest
    environment: induscode-actions
    timeout-minutes: 30

    # Read-only: IndusCode runs in this job.
    permissions:
      contents: read
      issues: read

    steps:
      - name: Checkout repository
        uses: actions/checkout@v4
        with:
          persist-credentials: false

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22

      - name: Install IndusCode CLI
        run: npm install -g induscode

      - name: Configure IndusCode Authentication
        env:
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
        run: |
          induscode auth --provider openrouter \
            --apikey "$OPENROUTER_API_KEY" \
            --modelid anthropic/claude-sonnet-5.5

      - name: Run analysis
        env:
          GH_TOKEN: ${{ github.token }}
          ISSUE_URL: ${{ github.event.issue.html_url }}
          COMMENT: ${{ github.event.comment.body }}
        run: |
          set -euo pipefail
          bash git-scripts/analyze-issue.sh "$ISSUE_URL" "Analyze this issue. The user asked: $COMMENT" > response.md

      - name: Save the response
        uses: actions/upload-artifact@v4
        with:
          name: response
          path: response.md
          if-no-files-found: error

  post:
    needs: analyze
    runs-on: ubuntu-latest
    timeout-minutes: 5

    # Can write issues, but runs no code from the repository or from IndusCode.
    permissions:
      issues: write

    steps:
      - name: Download the response
        uses: actions/download-artifact@v4
        with:
          name: response
          path: ${{ runner.temp }}/response

      - name: Post the response
        env:
          GH_TOKEN: ${{ github.token }}
          GH_REPO: ${{ github.repository }}
          ISSUE_NUMBER: ${{ github.event.issue.number }}
        run: gh issue comment "$ISSUE_NUMBER" --body-file "$RUNNER_TEMP/response/response.md"
```
</Accordion>

The workflow has three jobs, so that only people who can write to the repository can start IndusCode, and the job that runs IndusCode can't change your repository or your issues:

1. **`authorize`** runs when someone mentions `@induscode` in an issue comment. It looks up the comment author's permission on the repository, and the workflow stops unless they can write to it. GitHub reports the maintain role as write.
2. **`analyze`** gets a read-only token, runs the analysis script from your repository, and saves IndusCode's answer to a file.
3. **`post`** gets permission to write issues, but doesn't check out code or run IndusCode. It posts the file as a comment on the issue.

Add your AI provider API keys as repository secrets:

### 3. Add Analysis Script

Add the analysis script from the `github-issue-rca` sample to your repository, in a `git-scripts` directory at the repository root. Create the directory and file, then paste the script content:

```bash
# In your repository root
mkdir -p git-scripts
# Create and edit the file with your preferred editor
nano git-scripts/analyze-issue.sh  # or use vim, code, etc.
```

<Accordion title="Click to view the complete analyze-issue.sh script">
```bash
#!/bin/bash
# Analyze a GitHub issue using IndusCode CLI

if [ -z "$1" ]; then
    echo "Usage: $0 <github-issue-url> [prompt]"
    echo "Example: $0 https://github.com/owner/repo/issues/123"
    echo "Example: $0 https://github.com/owner/repo/issues/123 'What is the root cause of this issue?'"
    exit 1
fi

# Gather the args
ISSUE_URL="$1"
PROMPT="${2:-What is the root cause of this issue?}"

# Fail if IndusCode fails, not only if jq does
set -o pipefail

# Ask IndusCode for its analysis, showing only the summary
induscode --auto-approve true --json "$PROMPT: $ISSUE_URL" | \
    jq -r 'select(.type == "run_result") | .text'
```

After pasting the script content, make it executable:
```bash
chmod +x git-scripts/analyze-issue.sh
```
</Accordion>

This analysis script calls IndusCode to execute a prompt on a GitHub issue and
prints IndusCode's final answer, which becomes the reply to the issue.

### 4. Commit and Push

```bash
git add .github/workflows/induscode-responder.yml
git add git-scripts/analyze-issue.sh
git commit -m "Add IndusCode issue assistant workflow"
git push
```

## Usage

Once set up, simply mention `@induscode` in any issue comment:

```text
@induscode what's causing this error?

@induscode analyze the root cause

@induscode what are the security implications?
```

**Note**: The workflow only triggers on issue comments, not pull request
comments, and only for comments from people with write access to the repository.

## How It Works

The workflow (`induscode-responder.yml`):

1. **Triggers** on issue comments (created or edited) that mention `@induscode`
2. **Checks** that the comment's author can write to the repository
3. **Installs** IndusCode CLI globally using npm
4. **Configures** authentication using `induscode auth --provider openrouter --apikey ... --modelid ...`
5. **Runs** `git-scripts/analyze-issue.sh` from your repository, which runs IndusCode in Act mode with auto-approval
6. **Posts** the analysis as a comment, from a separate job that doesn't run IndusCode

## What the Analysis Job Can Still Do

With `--auto-approve true`, IndusCode can run any shell command in the `analyze` job. Text in the issue or the comment could persuade IndusCode to do something other than analyze it. The read-only token stops IndusCode from changing your repository or issues, but the job can still read your code and your provider API key, and it can reach the internet. Use a provider key with a spending limit, and don't give the job any other secrets.
